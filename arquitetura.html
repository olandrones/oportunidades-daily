§0 TL;DR

Sistema de kanban interativo onde cada movimento de card é salvo online (jsonbin.io) e sincronizado em todos os devices. O código fica em GitHub Pages; os dados ficam em jsonbin. localStorage é cache offline. Hermes (eu) leio e escrevo via API quando você me pede.

┌─────────────┐ GET /latest ┌──────────────┐ API key ┌─────────────┐ │ NAVEGADOR │ ─────────────▶ │ JSONBIN.IO │ ◀──────────── │ HERMES │ │ (você) │ ◀───────────── │ (bin priv.) │ ────────────▶ │ (eu, .env) │ └─────────────┘ PUT (drag) │ bin: 6a2ee7c6 └─────────────┘ ▲ └──────────────┘ │ serve HTML ▲ │ │ PUT direto ┌─────────────┐ │ │ GITHUB PAGES│ ────────────── └───┘ │ (crescer.html)│ └─────────────┘

1 usuário · 1 bin · 1 chave · 1 página. Sem backend customizado. Sem webhook. Sem servidor rodando. Tudo declarativo e versionado em olandrones/oportunidades-daily.

§1 Princípios

1. Onde houver movimento, há dado

Todo drag, criação, edição, arquivamento vira evento persistido. Nada "vive só na tela".

2. Schema antes de UI

O JSON é a fonte da verdade. A página é só uma view dele. Posso trocar a UI inteira sem perder dados.

3. Offline-first, online-quando-puder

localStorage é a primeira camada. jsonbin sincroniza quando há rede. Falha de rede ≠ falha do sistema.

4. Decisões explícitas, defaults explícitos

Cada coluna, cada campo, cada status tem nome. Nada implícito, nada "mágico".

5. Humano + agente escrevem no mesmo lugar

Card criado por você tem autor: "renato". Criado por mim, autor: "hermes". Mesma estrutura, mesma view.

6. Pior é "tá funcionando" sem entender por quê

14/06 O fix do 401 e o UT truncado ensinaram: a feature "online" não é "passa na URL". Tem que verificar.

O que NÃO está aqui (por design)

  • Backend: nenhum servidor próprio. jsonbin é o "banco".
  • Webhook: sync é client-driven (PUT a cada drag). Sem push real-time.
  • Auth de usuário: a X-Master-Key é o gatekeeper. Trocar por X-Access-Key se quiser compartilhar read-only.
  • Histórico de versões: o jsonbin guarda o último estado. Histórico de edits não existe (ainda).

§3 Fluxo de dados

3.1 — Abrir a página (cold start)

[1] navegador carrega crescer.html do GH Pages [2] JS roda → load() [3] lê localStorage["crescer:incubadora:v1"] → se existe, pinta UI [4] em paralelo: fetch GET .../b/{BIN}/latest → se 200, sobrescreve localStorage [5] se nenhum dado em lugar nenhum → semeia (4 cards seed) e PUT [6] indicador: ● verde "jsonbin" ou ● amarelo "sincronizando" ou ● rosa "offline"

3.2 — Drag de card

[1] usuário arrasta 🎸 de 🌱 semente pra 💡 ideia [2] SortableJS dispara onAdd [3] JS move o card no DATA em memória [4] localStorage.setItem(...) // IMEDIATO, sem rede [5] setSync("dirty") + debounce 500ms [6] fetch PUT .../b/{BIN} com X-Master-Key [7] resposta 200 → ● verde "jsonbin" resposta != 200 ou erro de rede → ● rosa "offline" (tenta próximo drag)

3.3 — Criar card novo (botão +)

[1] usuário clica + → modal "nova ideia" [2] preenche: emoji · título · tagline · coluna inicial [3] + criar → cria {id, autor:"renato", updates:[{novo}]} [4] push no DATA.columns[col].cards [5] PUT debounced ao jsonbin (mesmo passo 3.2-[5])

3.4 — Direcionamento (input "pra onde crescer")

[1] usuário clica no card → modal [2] digita no "novo direcionamento" [3] 💾 salvar → push em card.direcionamentos[] com status: "pendente" [4] também appenda em card.updates[] com tipo: "dir" [5] PUT debounced
💡 Próximo passo (não implementado ainda)

Quando um direcionamento novo chega com status: "pendente", o Hermes seria notificado e geraria um insight/update. Hoje isso só acontece se você vier falar comigo dizendo "olha o direcionamento do card X".

3.5 — Container (mistura de ideias)

[1] usuário arrasta 2+ cards pra coluna 📦 containers [2] SortableJS onAdd num container vazio → cria container novo com nome "novo container" [3] ou se arrasta pra um já existente → adiciona ao array container.cards [4] renomear: input editável inline (onchange salva direto) [5] deletar: botão × → devolve cards pra ideia e remove o container [6] PUT debounced

§4 Schema de dados

O bin armazena 1 objeto JSON com esta estrutura. Cada card tem id estável (string) — usado pra drag, referência, e idempotência.

// Bin: 6a2ee7c6da38895dfebf95d8
{
  "version": "2.0",                          // schema version (semver)
  "updated_at": "2026-06-14T13:45:00Z",       // ISO 8601
  "columns": [
    {
      "id": "semente",                       // slug, usado em drag/drop
      "label": "🌱 semente",                // texto visível, pode ter emoji
      "cards": [
        {
          "id": "c1",                        // string única, gerada no create
          "emoji": "🎸",                     // 1-2 chars
          "title": "App Violão",             // obrigatório
          "tagline": "campos harmônicos visuais no braço + MIDI",
          "autor": "renato" | "hermes",    // quem criou
          "tags": ["urgente", "framework"], // tags livres, classes CSS por nome
          "direcionamentos": [
            { "ts": "...", "texto": "...", "status": "pendente"|"processado" }
          ],
          "updates": [
            { "ts": "...", "tipo": "scaffold"|"PRD"|"dir"|"novo"|..., "texto": "..." }
          ]
        }
      ]
    },
    { "id": "ideia", "label": "💡 ideia", "cards": [...] },
    { "id": "pesquisar", "label": "🔍 pesquisar", "cards": [...] },
    { "id": "aprofundar", "label": "🧪 aprofundar", "cards": [...] },
    { "id": "desenvolver", "label": "🛠️ desenvolver", "cards": [...] }
  ],
  "containers": [                            // mistura de ideias
    {
      "id": "cont-1718376000000",             // cont-{timestamp}
      "name": "música + IA",                // editável inline
      "cards": [ /* refs por id ou objects? hoje: objects */ ]
    }
  ]
}

Invariantes

  • Cada id é único dentro de columns[].cards[] e containers[].cards[].
  • version é obrigatório. Mudou → breaking. Migrar ou forkear.
  • autor ∈ {renato, hermes}. Hoje livre, mas pode virar enum.
  • tags são strings livres, mas só as seguintes têm cor CSS hoje: urgente (vermelho), framework (amarelo).
  • direcionamentos[].status ∈ {pendente, processado}. Hermes transita pra processado quando responde.
  • Card em 🛠️ desenvolver é a única coluna que pode ter link pra TRD (futuro: campo trd_slug).

§5 API (jsonbin v3)

Base: https://api.jsonbin.io/v3 · Auth header: X-Master-Key: $2a$10$...

MétodoEndpointUsoHeaders obrigatórios
GET /b/{BIN_ID}/latest Carregar estado no load() e no refresh X-Master-Key
PUT /b/{BIN_ID} Salvar estado (debounced 500ms) X-Master-Key, Content-Type: application/json
POST /b Criar novo bin (setup inicial, "100 pessoas") X-Master-Key, X-Bin-Name, Content-Type
DELETE /b/{BIN_ID} Resetar tudo (cuidado! — backup primeiro) X-Master-Key

Content-Type: application/json

{
  "version": "2.0",
  "updated_at": "2026-06-14T18:23:45.123Z",
  "columns": [ ... ],
  "containers": [ ... ]
}
⚠️ Rate limit

jsonbin.io free tier = 100 req/hora por bin. O debounce de 500ms + "só salva se houve mudança" deixa a gente em ~5-10 req/hora de uso real. Sobra 90% pra Hermes e admin.

§6 Modos de falha & recuperação

CenárioSintomaMitigação automáticaRecovery manual
jsonbin offline Indicador: ● rosa "offline" localStorage continua funcionando. PUT é descartado silenciosamente. Esperar jsonbin voltar. Próximo PUT reenvia o estado inteiro.
X-Master-Key inválida / rotacionada Indicador: ● "jsonbin: 401" localStorage serve a UI. Sem sync. Gerar nova key no painel jsonbin → atualizar .env + inline no JS → commit + push.
localStorage cheio ou bloqueado Sem ícone (silent) jsonbin continua funcionando como fonte. Limpar via DevTools: localStorage.clear(); location.reload()
CORS preflight bloqueado (raro) Indicador: ● "offline" sem 401 localStorage continua. jsonbin mudou política. Reportar bug.
Bug no código (ex: write_file truncou key) Indicador: ● "jsonbin: 401" — Conferir tamanho real da key (grep -oE + wc -c). 14/06 aprendemos a conferir.
Dois devices editando ao mesmo tempo Último PUT ganha. Sem merge. — Decidir quem "tem a versão boa" e fazer PUT dela.
Schema quebrado após update Página branca ou erro JS Cache localStorage pode estar ok. Tentar Ctrl+Shift+R. Limpar localStorage, voltar pra version anterior do git, esperar fix.

§7 SOP — Manutenção

Dois atores: humano (Renato) e agente (manutenção). Tudo abaixo é executável como job, script, ou comando.

7.1 — SOP diário (manutenção automática, pausado)

  1. curl -sI https://olandrones.github.io/oportunidades-daily/crescer.html → 200?
  2. curl -sI -H "X-Master-Key: $KEY" https://api.jsonbin.io/v3/b/{BIN}/latest → 200?
  3. Verificar version no GET. É igual à SUPPORTED_VERSION hardcoded no HTML? Se não, alerta.
  4. Contar cards por coluna. Anomalia (delta >3 vs média móvel 7d)? Reportar.
  5. Contar cards com direcionamentos[status="pendente"] > 7 dias. Marcar pra revisão.
  6. Reportar tudo pro Renato via Telegram. SEMPRE, mesmo que "tudo ok" (princípio 6).

7.2 — SOP ao adicionar/modificar coluna

  1. Editar crescer.html: adicionar objeto em SEED().columns E no array columns da seed no bin.
  2. Testar local: python -m http.server 8000 em E:\00 - Hermes System\repos\oportunidades-daily, abrir localhost:8000/crescer.html.
  3. Confirmar que card drag funciona entre TODAS as colunas (não só a nova).
  4. Atualizar version no JSON (2.0 → 2.1) se mudou schema.
  5. git add crescer.html && git commit -m "feat(col): add 'pausada' column" && git push origin main
  6. Aguardar deploy (~60s) e validar com curl.
  7. Avisar Renato: "coluna 'X' adicionada, schema v2.1".

7.3 — SOP ao rotacionar a X-Master-Key

  1. Login em jsonbin.io → Settings → Generate New Master Key.
  2. Copiar nova key (60 chars, começa com $2a$10$).
  3. Atualizar C:\Users\Darida\.hermes\.env → JSONBIN_API_KEY=...
  4. Atualizar inline em crescer.html linha 497: const API_KEY = '...nova...'
  5. Conferir: grep -oE "'[^']{58,62}'" crescer.html → deve ter 60 chars.
  6. Commit + push. Aguardar deploy.
  7. Limpar localStorage no browser do Renato: localStorage.clear(); location.reload() (forçar re-fetch com nova key).
  8. Confirmar que indicador fica ● verde.

7.4 — SOP ao recuperar de corrupção

  1. Verificar git log no repo. Qual a última versão "boa" do JSON?
  2. Se jsonbin tem dados bons: curl -s -H "X-Master-Key: $KEY" .../b/{BIN}/latest > backup.json
  3. PUT manual: curl -X PUT -H "X-Master-Key: $KEY" -H "Content-Type: application/json" --data @backup.json .../b/{BIN}
  4. Limpar localStorage e recarregar.
  5. Se jsonbin corrompido E localStorage tem versão boa: localStorage.getItem("crescer:incubadora:v1") no DevTools, copiar, salvar como backup.json, seguir passo 3.
  6. Se ambos corrompidos: restaurar seed-crescer.json que está em E:\01 - Team Claw\hermes - Lyriane\ (sempre).

7.5 — SOP ao criar um agente novo pra incubadora

  1. Definir escopo: o agente LÊ, ESCREVE, ou AMBOS? Que tipos de card? Que colunas?
  2. Escrever prompt em E:\00 - Hermes System\agentes\agente-{nome}.md (template em maintenance-agent-pattern).
  3. Se agente escreve: SEMPRE usar autor: "hermes" + tag hermes no card.
  4. Adicionar job em cron\jobs.json com enabled: false inicialmente.
  5. Testar manualmente: hermes cronjob run {job_id} e ver o que ele fez.
  6. Se ok: cronjob update ... enabled=true.
  7. Adicionar linha em visao.json linkando agente ↔ job (accountability).

8.3 — Cache-busting no browser do Renato

Como o CDN do GH Pages cacheia HTML, pedir pro Renato usar Ctrl+Shift+R (hard refresh) ou adicionar ?v=2 na URL.

Long-term: adicionar <meta http-equiv="cache-control" content="no-cache"> no <head> ajuda no browser do Renato (CDN ignora).

§9 Onboarding — "100 pessoas"

Cada pessoa que quiser usar esse sistema precisa de 3 coisas. O resto é template.

  1. Criar conta no jsonbin.io (free tier = 100 req/hora, suficiente pra 1 pessoa).
  2. Criar um bin: POST /b com X-Master-Key da conta, X-Bin-Name: incubadora, X-Bin-Private: true, body = seed JSON.
  3. Copiar Bin ID (formato 6a2ee7c6da38895dfebf95d8) e X-Master-Key.
  4. Fork do repo olandrones/oportunidades-daily.
  5. Substituir em crescer.html:
    • linha 496: const BIN_ID = '...'
    • linha 497: const API_KEY = '...'
  6. Habilitar GH Pages no fork (Settings → Pages → Source: main → /root).
  7. Customizar seed (linha 502+):
    • Trocar 🌱 semente, 💡 ideia, etc. pelos labels preferidos.
    • Adicionar/remover colunas.
    • Trocar autor: "renato" por autor: "marina" (ou o nome).
  8. Commit + push. URL: https://{user}.github.io/oportunidades-daily/crescer.html.
